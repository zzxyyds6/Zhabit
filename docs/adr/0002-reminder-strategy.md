# ADR-0002: 提醒策略——系统通知为默认,浮窗为可选增强

- 状态:已接受,具体实现方案待技术预研(issue #9,结论将写入 ADR-0003)
- 决策人:Zhao(与 agent 讨论后确认)

## 背景

PRD 要求固定/随机间隔提醒,最终形态是"灵动岛式"浮窗;但浮窗依赖 SYSTEM_ALERT_WINDOW 权限且实现方案未经验证,不能直接认定。

## 决策

1. **方向:Flutter + 原生 Kotlin 混合**(调度与浮窗涉及系统层能力)。
2. **默认提醒方式:系统通知**(离线可用、权限模型简单、无需浮窗权限)。
3. **浮窗是可选增强**,不是 MVP 前提;其实现方案必须先经 **issue #9 技术预研**验证,结论写入 ADR-0003 后才动工(issue #10)。
4. 业务层通过**平台接口**调用提醒能力(见 ADR-0001 第 3 条),接口设计在 issue #1 落地。

## 预研必须验证的四项(issue #9)

1. 后台定时提醒(精确闹钟调度)
2. 设备重启后的提醒恢复
3. 浮窗显示与浮窗内交互(直接打卡)
4. 权限被拒时的退化链路(浮窗→通知→设置页提示)
